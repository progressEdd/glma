The function must produce markdown with these sections in order:

### Header
```markdown
# Architecture Overview

**Generated:** {datetime.now(timezone.utc).isoformat()}
**Total Modules:** {N}
```

### Section 1: Project Structure Overview
- Group files by their directory segment. For each file path in `file_data`, extract the module name using this logic:
  - Split path by `/`
  - If path has >= 3 segments (e.g., `src/glma/db/ladybug_store.py`), the module name is the directory between source root and filename (e.g., "db")
  - If path has < 3 segments (e.g., `src/glma/cli.py`), use the filename stem as a "root" module (e.g., "cli")
  - Group `__init__.py` files with their directory module
- For each module, list its files in a table:
```markdown
## Module: {module_name}

| File | Chunks | Summary |
| ---- | ------ | ------- |
| {relative path} | {count} | {file summary, truncated to 80 chars} |
```
- Module narrative: After the table, add a paragraph composed from chunk summaries. Collect all chunks in the module. For each chunk with a `summary` field (AI summary), add `"{chunk.name}: {chunk.summary}"`. If no chunks have summaries, use `generate_rule_summary()` on each file to produce a fallback description. Join with "; ". Truncate to 300 chars with "..." if needed.

### Section 2: Module Dependency Graph
- Compute inter-module dependencies from relationship data:
  - For each file's relationships, extract outgoing imports/calls where the target file belongs to a different module
  - Aggregate into module-level edges: `module_deps[source_module].add(target_module)`
- Render as adjacency table:
```markdown
## Module Dependencies

| Module | Depends On |
| ------ | ---------- |
| {module} | {comma-separated list of dependent modules} |
```
- If a module has no dependencies, show "*(no external dependencies)*"

### Section 3: Entry Points
- **Convention detection:** Check each file path in `file_data` for:
  1. `__main__.py` filename → "detected entry point"
  2. `cli.py` or `main.py` filename → "detected entry point"
  3. Check each chunk's `content` field for the string `if __name__ == "__main__"` → "detected entry point" for that file
- **Fan-in analysis:** For each file, count incoming import relationships (where `direction == "incoming"` and `rel_type == "imports"`). Files with zero incoming imports AND at least one outgoing import/call → "likely entry point"
- Render as table:
```markdown
## Entry Points

| File | Detection Method | Key Chunks |
| ---- | ---------------- | ---------- |
| {path} | {detected entry point / likely entry point} | {top-level chunk names} |
```
- Exclude files that are both convention-detected AND fan-in detected (show only once, as "detected entry point")

### Section 4: Key Interfaces
- For each chunk across all files, count incoming relationships (imports + calls from other files)
- Sort by incoming count descending, take top 10
- Render as table:
```markdown
## Key Interfaces

| Name | Type | File | Used By (files) |
| ---- | ---- | ---- | --------------- |
| {chunk.name} | {chunk_type} | {file_path} | {count} files |
```
- Include chunk summary in parentheses after the name if available

### Helper functions
Add these private helpers before `generate_architecture_md()`:
- `_get_module_name(file_path: str) -> str` — extract module name from path
- `_group_by_module(file_data: dict[str, dict]) -> dict[str, list[str]]` — return {module_name: [file_paths]}
- `_detect_entry_points(file_data: dict[str, dict]) -> list[dict]` — return list of {path, method, chunks}
- `_compute_key_interfaces(file_data: dict[str, dict]) -> list[dict]` — return sorted list of {name, type, file, used_by_count, summary}

All helpers must use only data from the `file_data` dict — no store queries.
